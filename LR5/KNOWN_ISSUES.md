# Вопросы для согласования перед защитой

## 1. Прототип Backend `rating_service` использует другую шкалу

При локальном запуске `LR3/Markov/rating_service/main.py` выводит среднюю оценку `3.33` и `GPA = 2.0`, а в логике есть пороги вроде `3.5`. Это **не соответствует принятой для Analytics системе 0–54 балла** и независимым модулям 1/2. В `LR3/Khan` прототип использует 54-балльную систему и не смешивает модули. Код Маркова **не изменён**, чтобы не переписать чужую лабораторную без согласования. Команде нужно решить, служит ли его `rating_service` лишь старым демонстрационным примером или должен быть переработан под общую доменную модель.

## 2. Диаграммы показывают проектные интеграции

Сводная схема содержит gRPC и PostgreSQL как проектные связи. Наличие стрелок в C4 **не означает**, что Python-прототипы взаимодействуют по gRPC или используют общую БД. Для реальной разработки понадобятся protobuf-контракты, определения событий, настройки авторизации и тестирование межсервисного взаимодействия. Это вне объёма ЛР5 о Diagrams-as-Code.

## 3. GitHub Actions ещё нужно запустить на GitHub

Локально проверено: 22 PlantUML, 22 PNG, 22 SVG, отрицательный тест с ошибкой (код завершения 1), 15 тестов Khan и 27 тестов Naumov. Настоящего GitHub Actions run, Pull Request и одобрения тимлида в этой локальной сборке **пока нет**. Их скриншоты нельзя подменять локальными результатами.

## 4. Миграция старых файлов GitHub

В прежней структуре часть `.puml` лежала в корне репозитория, а `rating_service/` — отдельным каталогом. В этом комплекте те же материалы распределены по фамилиям внутри LR1–LR4. После импорта в существующий репозиторий тимлиду нужно проверить отсутствие устаревших дубликатов в корне и сохранить понятную историю изменений через Git. **Не удалять оригиналы до сравнения их с новой раскладкой.**
