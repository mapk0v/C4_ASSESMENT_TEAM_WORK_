# Отчёт по лабораторной работе №5 — Хан, Analytics

**Дисциплина:** Информационные системы и технологии.  
**Тема:** «C4 Model. Интеграция, сборка проекта».  
**Проект:** «Разработка ИС для учёта и анализа результатов промежуточной аттестации».  
**Исполнитель:** Хан К.А., группа ИДБ-23-12 (проверить точные реквизиты титульного листа).  

## 1. Цель работы

Интегрировать индивидуальные диаграммы C4 для подсистемы Analytics в единый репозиторий проекта, реализовать подход Diagrams-as-Code, проверить корректность PlantUML-кода и освоить процесс Pull Request и автоматической сборки в GitHub Actions.

## 2. Исходные материалы

В лабораторной работе №2 разработана диаграмма компонентов Analytics: `LR2/Khan/LR2_component_diagramm_SAaR.puml`. На ней показаны обработчик заданий, планировщик, калькулятор рейтинга `rating_calc`, детектор групп риска, построитель отчётов и репозиторий данных. В лабораторной работе №3 разработаны UML-диаграмма классов и Python-прототип вычисления рейтинга. В лабораторной работе №4 построены диаграммы L0, Dynamic и Deployment подсистемы.

По предметной области баллы за дисциплину задаются целым числом от 0 до 54. Интервалы: 45–54 — «отлично»; 35–44 — «хорошо»; 25–34 — «удовлетворительно»; 0–24 — «не сдал». Результаты первого и второго модулей хранятся и обрабатываются раздельно.

## 3. Интеграция архитектурных диаграмм

Материалы подсистем объединены в папках `LR2/Khan`, `LR3/Khan`, `LR4/Khan`. Сводная диаграмма `src/main.puml` отражает межконтейнерные связи: `api_gateway → analytics_service` для запуска расчёта, `analytics_service → notification_service` для событий о группах риска и обращения сервисов к PostgreSQL. Для исключения расхождения ID введён глоссарий `LR5/GLOSSARY_IDS.md`.

**Место для скриншота 1:** структура репозитория GitHub с папками Analytics и файлом `.github/workflows/render-docs.yml`.

## 4. Автоматическая проверка и генерация изображений

В проект добавлена конфигурация `.github/workflows/render-docs.yml`, запускаемая при push, Pull Request в `main` и ручном старте. Она устанавливает Java и Graphviz, загружает проверенную версию PlantUML, запускает единый скрипт `scripts/render-diagrams.sh` и загружает PNG/SVG как артефакт сборки.

При синтаксической ошибке проверка возвращает ненулевой код и изображения заново не генерируются; исправление выполняет автор PR. Библиотека C4 подключена локально из `LR4/vendor/C4-PlantUML`. Это делает проверку независимой от внешних `!include` по URL.

**Место для скриншота 2:** открытый workflow `render-docs.yml` на GitHub.

**Место для скриншота 3:** лог успешного запуска GitHub Actions после реального push или PR.

## 5. Результаты проверки

До публикации проведена локальная проверка 22 диаграмм PlantUML, включая общую `src/main.puml`. Все они успешно прошли синтаксический анализ и были экспортированы в PNG/SVG (по 22 файла каждого формата). Для ЛР3 Analytics ранее пройдены 15 автоматических тестов Python.

Также выполнена отрицательная проверка: при временно добавленном файле с ошибкой PlantUML скрипт завершился с кодом `1` и указал проблемный файл. Тестовый файл удалён из итогового комплекта.

**Место для скриншота 4:** вкладка Actions с зелёным статусом. Заполнить после подтверждения онлайн.

**Место для скриншота 5:** список артефактов `c4-architecture-diagrams` и сгенерированная сводная схема.

## 6. Работа с Git и Pull Request

Локальные изменения разработчика Analytics необходимо внести в feature-ветке `feature/khan-lr5-analytics`, затем создать Pull Request в `main`. Тимлид проводит Code Review: проверяет соответствие глоссарию ID, протоколы межсервисных связей и успешность сборки. После одобрения изменения сливаются в основную ветку.

**Место для скриншота 6:** созданный PR и комментарии/одобрение тимлида (после выполнения на GitHub).

## 7. Вывод

Индивидуальные архитектурные материалы Analytics подготовлены к интеграции в единый репозиторий, а PlantUML-код и генерация PNG/SVG проверены локально. После публикации в GitHub остаётся подтвердить успешное выполнение CI и прохождение Pull Request через Code Review. Это обеспечит воспроизводимую архитектурную документацию и контроль корректности изменений.
