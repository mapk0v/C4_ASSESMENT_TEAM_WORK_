# Соответствие C4 L2 → L3 → L4

| Уровень | Сущность | Роль |
| --- | --- | --- |
| L2 | `analytics_service` | Контейнер: Сервис аналитики и рейтинга |
| L3 | `analytics_coordinator` | Вызывает расчёт аналитических показателей |
| L3 | **`rating_calc`** | Выбранный компонент: калькулятор рейтинга |
| L3 | `analytics_repo` | Источник оценок и точка записи вычисленных результатов |
| L4 | `RatingCalculator` | Контекст паттерна Strategy; выбирает модуль и валидирует вход |
| L4 | `RatingStrategy` | Общий интерфейс вычислительного алгоритма |
| L4 | `AverageStrategy`, `MedianStrategy`, `MinimumStrategy` | Взаимозаменяемые стратегии |
| L4 | `ModuleGrade`, `Student`, `Discipline`, `RatingSummary` | Доменные структуры |

## Предлагаемый вызов через существующий компонент

1. Backend запрашивает расчёт по `student_id`, `academic_year`, `module` через gRPC-обработчик аналитики.
2. `analytics_coordinator` выбирает нужный алгоритм и получает оценки через `analytics_repo`.
3. `rating_calc` вычисляет показатель **только по выбранному модулю** и возвращает `RatingSummary`.
4. Координатор может передать результат в репозиторий для сохранения, затем ответить Backend.

Это описание **контракта интеграции**, а не реализованный здесь gRPC/SQL-сервис. Сигнатура программного прототипа: `calculate_rating(student, academic_year, module, grades) -> RatingSummary`. На C4 L3 взаимодействия внутри сервиса остаются `in-process`, а вызов Backend → Analytics — `gRPC/HTTP2`.

## Почему в реализации нет Pandas / NumPy

В согласованной L3-диаграмме `rating_calc` подписан как Python / Pandas / NumPy. Для прототипа L4 с 6 дисциплинами выбрана стандартная библиотека Python: она позволяет наглядно показать интерфейсы, Type Hinting, Strategy и тесты без ненужных зависимостей. **Это сужение технологического стека в учебном прототипе, а не утверждение об изменении L3-архитектуры.** При реализации полноценного сервиса могут использоваться Pandas/NumPy для больших выборок.
