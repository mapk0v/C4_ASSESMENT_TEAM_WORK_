# ИСИТ — общая архитектура C4 и лабораторная работа №5

**Тема:** «Разработка ИС для учёта и анализа результатов промежуточной аттестации» (МГТУ «СТАНКИН»).

Проект объединяет диаграммы C4, UML-классы прототипов и процесс автоматической проверки PlantUML. Баллы за дисциплину имеют диапазон **0–54**: 0–24 — «не сдал», 25–34 — «удовлетворительно», 35–44 — «хорошо», 45–54 — «отлично». Оценки первого и второго модулей независимы.

## Структура ЛР5

- `.github/workflows/render-docs.yml` — GitHub Actions при `push` и `pull_request` в `main`.
- `scripts/render-diagrams.sh` — единая локальная/CI-команда проверки и отрисовки.
- `src/main.puml` — сводная C4-диаграмма контейнеров с ID всех трёх сервисов.
- `LR4/vendor/C4-PlantUML/` — локальная библиотека C4; рендеринг не требует подключения к `raw.githubusercontent.com`.
- `docs/images/` — локально сгенерированные PNG/SVG (сохраняется структура каталогов).
- `LR5/GLOSSARY_IDS.md` — единый словарь идентификаторов.
- `LR5/TEAM_GUIDE.md` — шаги тимлида и участников для GitHub и защиты.
- `LR5/Khan/REPORT.md` — индивидуальный текст отчёта Analytics с местами для скриншотов.
- `LR5/CHANGELOG.md` — исправления для интеграции.
- `LR5/KNOWN_ISSUES.md` — открытые вопросы, включая старый формат оценки в прототипе Маркова.

## Проверка диаграмм локально

Требуются **Java 17+**, **Graphviz**, **PlantUML JAR**. Для локальной проверки и CI закреплена одна версия PlantUML **1.2025.10** с проверкой SHA-256 при загрузке в GitHub Actions.

```bash
bash scripts/render-diagrams.sh /absolute/path/to/plantuml.jar
```

Скрипт проверяет **22 самостоятельные диаграммы** (`LR1`–`LR4` и `src/main.puml`), исключает библиотечные макросы из `LR4/vendor`, прекращает работу с кодом ошибки при некорректном PlantUML, затем создаёт PNG и SVG. Для рендеринга применяется `-DRELATIVE_INCLUDE=1` — это необходимо для локальных вложенных импортов библиотеки C4.

Отдельно можно проверить код Analytics:

```bash
cd LR3/Khan
python -m unittest discover -s tests -v
python main.py
```

## GitHub Actions

После размещения **содержимого этой папки в корне репозитория** GitHub автоматически запустит `render-docs.yml` при PR и push в `main`. Результаты доступны в `Actions → [запуск] → Artifacts → c4-architecture-diagrams`. Успешный локальный запуск **не равен** зелёному статусу GitHub: реальную CI-проверку требуется провести после публикации.

В уже существующем GitHub-репозитории часть старых диаграмм лежит прямо в корне. При переносе нужно сверить их с файлами новых папок и не оставить непонятные дубликаты; см. `LR5/KNOWN_ISSUES.md`.

Workflow сознательно **не выполняет автоматический `git push`**: у него права только на чтение, он загружает PNG/SVG как артефакт и безопасно работает на Pull Request. При необходимости в будущем можно согласовать с тимлидом отдельную публикацию изображений в `docs/images`.

## Как сдавать

Индивидуальные изменения оформляются в feature-ветках и Pull Request, которые проверяет тимлид. Скриншоты PR, зелёной галочки CI, логов и артефактов добавляются к отчёту уже после реального запуска на GitHub. Подробная инструкция — `LR5/TEAM_GUIDE.md`.
